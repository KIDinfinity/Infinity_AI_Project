# 半年稳态成长 + 睡后收入 + AI能力沉淀

## 第1--8周短期目标详细执行与验收版

> 本文件是《半年稳态成长+睡后收入+AI能力沉淀终极落地计划·长期数字资产版》的**第1--8周执行细化版**。
>
> 本阶段不是为了"做完某一个指定项目"，而是完成短期目标：
>
> **建立可复用的个人数字资产研发底座，并完成至少一个候选数字产品从"想法
> → 验证 → 最小可用版本"的第一轮闭环，同时建立 AI Agent / RAG /
> 工程化的基础能力。**
>
> **预约小程序只是历史上的候选方案，不再作为本阶段的默认目标。**
>
> 产品可以最终是
> Web、App、桌面软件、CLI、插件、Agent、API、自动化工具、开发者工具、数字产品、开源项目、某个独立功能等。
>
> **原则：目标决定产品形态，产品形态决定技术方案，技术方案最后才决定技术栈。**

------------------------------------------------------------------------

# 一、8周结束时必须达到什么状态

## 1. 短期总目标

8周结束时，应同时形成以下四类成果：

### A. 数字资产研发底座

具备一个自己能够长期维护的基础环境：

-   Docker 环境稳定可用
-   Gitea 或等价代码仓库可用
-   MinIO 或等价对象存储可用
-   Qdrant 或等价向量数据库可用
-   项目目录、Git 分支、环境变量、配置文件有统一规范
-   至少完成一次备份
-   至少完成一次恢复测试
-   新项目可以按照统一模板快速创建

### B. 一个经过验证的数字产品候选

不是要求第8周就正式赚钱，而是要求：

> **已经证明"这个东西值得继续做"，或者明确证明"这个方向不值得继续做"。**

必须完成：

-   问题定义
-   目标用户定义
-   使用场景
-   核心价值
-   候选产品形态
-   最小功能范围
-   基础竞争/替代方案观察
-   最小验证
-   MVP方案
-   第一版可运行原型或 MVP

如果原候选方案被验证为不值得继续开发，可以更换方向。

**"及时放弃错误方向"本身也是本周目标的有效结果。**

### C. AI Agent / RAG 基础能力

至少能够独立解释并跑通：

``` text
用户输入
  ↓
问题理解
  ↓
知识检索 / 工具调用
  ↓
上下文组织
  ↓
LLM
  ↓
结果输出
  ↓
基础评估 / Bad Case记录
```

并完成一个最小可运行实验。

### D. 第一套可复用工程方法

8周结束后，不只是"做了一个项目"，而是留下：

-   项目模板
-   Docker 配置
-   Git 规范
-   环境配置模板
-   README 模板
-   部署说明
-   备份恢复说明
-   AI/RAG 实验记录
-   产品验证记录
-   MVP 需求文档
-   周复盘记录

这些东西以后可以直接复制到第2个、第3个数字资产项目。

------------------------------------------------------------------------

# 二、执行总规则

## 每日时间

每天：

> **1--2小时**

原则：

> 时间不够就减少任务数量，不增加工作时间。

禁止：

-   为了完成计划熬夜
-   用主业时间做副业
-   为了技术炫技扩大项目范围
-   为了"学完再做"无限学习
-   同时启动多个产品
-   因为一个候选项目失败就认为整个计划失败

------------------------------------------------------------------------

# 三、三条工作线

短期8周保持三条线，但优先级明确：

``` text
C：个人工程 / 私有云基础设施
        ↓
A：数字产品验证与MVP
        ↓
B：AI Agent / RAG能力
```

实际时间建议：

  工作线         时间占比 目的
  ------------ ---------- ----------------------
  C 基础设施          30% 建立长期可复用底座
  A 数字产品          45% 直接产生数字资产
  B AI 能力           25% 建立未来产品的AI能力

> 第3周开始，A线是核心，不允许基础设施无限扩张。

------------------------------------------------------------------------

# 六、第3周：寻找并验证数字产品机会

## 周目标

> **停止默认"我要做什么技术"，开始回答"我要解决什么问题"。**

这一周非常重要。

**禁止直接进入开发。**

------------------------------------------------------------------------

## 本周任务

### 任务1：建立候选问题池

收集至少：

> **10个真实问题 / 痛点**

来源可以是：

-   自己工作中反复遇到的问题
-   开发者常见重复劳动
-   AI工具使用痛点
-   信息整理痛点
-   自动化需求
-   某类人群的重复操作
-   已经存在但体验很差的工具

------------------------------------------------------------------------

### 任务2：筛选3个候选

每个候选必须写：

``` text
问题：
谁有这个问题：
什么时候发生：
现在怎么解决：
现有方案有什么麻烦：
我能提供什么改进：
用户为什么可能愿意付费：
最小产品是什么：
```

------------------------------------------------------------------------

### 任务3：确定验证方案

每个候选至少设计一个低成本验证：

例如：

-   一个Landing Page
-   一个CLI原型
-   一个浏览器插件原型
-   一个Agent Demo
-   一个自动化脚本
-   一个可运行的小功能
-   一个交互原型
-   一个API Demo

**不要求正式产品。**

------------------------------------------------------------------------

## 本周最重要的测试

给每个候选回答：

### 5个问题

1.  用户是谁？
2.  用户现在怎么解决？
3.  这个问题是否足够频繁？
4.  最小解决方案是什么？
5.  如果只给我7天，我能做出什么？

如果其中3个以上回答不清楚：

> **不能进入开发。**

------------------------------------------------------------------------

## 第3周最终产物

形成：

``` text
10个问题
 ↓
3个候选
 ↓
1个主候选
 ↓
1个验证方案
```

同时允许：

``` text
10个问题
 ↓
3个候选
 ↓
发现都不成立
 ↓
继续寻找
```

这不是失败。

这是避免未来浪费100小时开发错误产品。

------------------------------------------------------------------------

## 第3周通过标准

-   [ ] 10个问题进入问题池
-   [ ] 3个候选完成结构化分析
-   [ ] 每个候选都有最小验证方案
-   [ ] 选出1个主候选或明确继续寻找
-   [ ] 能用3分钟解释主候选解决什么问题
-   [ ] 没有因为技术栈方便而强行选择产品

------------------------------------------------------------------------

# 八、第5周：数字产品原型 / MVP核心开发

## 周目标

> **从"方案"进入"可运行的东西"。**

本周不追求完整。

只做：

> **核心价值链。**

------------------------------------------------------------------------

## 开发原则

假设产品完整功能有：

``` text
A
B
C
D
E
F
```

本周只做：

``` text
A → B → C
```

只要用户能够通过这条链获得核心价值，就算成功。

------------------------------------------------------------------------

## 本周任务

### 任务1：核心流程开发

完成产品最重要的一条用户路径。

例如：

``` text
输入
→ 处理
→ AI
→ 结果
```

或：

``` text
打开
→ 执行核心功能
→ 获得结果
```

或者：

``` text
上传
→ 自动处理
→ 输出结果
```

具体形式根据第3--4周验证结果决定。

------------------------------------------------------------------------

### 任务2：AI协作开发

AI可以负责：

-   样板代码
-   UI
-   重构
-   测试
-   文档
-   错误定位

你负责：

-   产品逻辑
-   数据结构
-   核心架构
-   安全边界
-   最终验收

------------------------------------------------------------------------

### 任务3：记录开发资产

每天至少沉淀：

``` text
今天解决了什么
AI生成了什么
哪些地方需要人工判断
遇到什么坑
以后如何复用
```

------------------------------------------------------------------------

## 第5周验收测试

### 核心流程测试

从一个完全干净环境开始：

``` text
启动项目
→ 按README操作
→ 完成核心流程
→ 得到预期结果
```

要求：

> **核心流程连续跑通3次。**

### 错误测试

至少测试：

-   空输入
-   错误输入
-   边界输入
-   重复操作
-   网络/API失败

------------------------------------------------------------------------

## 第5周通过标准

-   [ ] 核心流程可运行
-   [ ] 连续成功3次
-   [ ] 至少5个异常场景有处理
-   [ ] README可以指导启动

# 十四、8周通过规则

不要用"感觉差不多"判断。

采用三个等级：

### PASS：通过

核心验收全部完成，可以进入第9周。

### CONDITIONAL：有条件通过

核心资产已经形成，但有1--2个非核心项目未完成。

处理方式：

> 第9周每天抽出最多20分钟补齐，不重新开启一个完整学习周期。

### FAIL：未通过

出现以下任一情况：

-   没有形成可运行的数字产品候选
-   没有完成核心流程
-   没有完成备份/恢复
-   没有完成基础RAG实验
-   大量时间消耗在与目标无关的技术学习
-   产品方向已经明显不成立但仍继续堆代码

处理方式：

> 不增加工作时间，不进入新复杂度；找到最小失败点，下一周优先修复。

# 十六、永久规则

1.  **产品形态永远不是预设答案。**
2.  **预约小程序只是候选，不是使命。**
3.  **不为了学习技术而做产品。**
4.  **不为了展示全栈能力而增加系统复杂度。**
5.  **先验证问题，再写代码。**
6.  **先做最小闭环，再扩功能。**
7.  **允许放弃错误产品，但不能放弃整个能力积累。**
8.  **每周必须有可验证结果。**
9.  **每8周必须形成可以留下来的数字资产。**
10. **所有经验必须沉淀成下一次可以复用的模板。**
11. **时间永远控制在每天1--2小时。**
12. **最终目标不是完成某一个项目，而是持续生产能够独立存在、重复交付、持续维护或产生收入的数字资产。**

------------------------------------------------------------------------
