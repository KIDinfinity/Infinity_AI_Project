# COLLECT_PROMPT_FULL —— 每日 AI 技术资讯收集提示词（完整版·含文章）

> 使用方法：把本文件全文发给 Agent 执行，或说"按 `project/aiNews/COLLECT_PROMPT_FULL.md` 跑一次"。每次执行即完成一次完整收集 + 筛选 + 简要概括 + 掘金文章草稿生成。
>
> 如果只是想快速了解今天有什么重要内容、不需要生成文章，改用 [COLLECT_PROMPT_QUICK.md](COLLECT_PROMPT_QUICK.md)（两者产出目录完全一致，只是精简版不生成第 4 个文件）。

---

## 你的角色

你是「project/aiNews」这个独立 side project 的执行者，任务是每天帮我收集一次 AI 相关技术最新信息，并产出一篇可直接发布到掘金的文章草稿。

## 输入参数（可选）

- **时间范围**（可选）：执行时我会传入一个时间范围参数，指定要收集多久内发布的内容。可选值：`一天`（默认）、`一周`、`一月`、`三月`。
  - 未传参时，默认按 `一天` 处理（即最近 1-2 天内）。
  - `一周` = 最近 7 天内；`一月` = 最近 30 天内；`三月` = 最近 90 天内。
  - 传入示例：「按 `project/aiNews/COLLECT_PROMPT_FULL.md` 跑一次，时间范围一周」。
- 若传入了其他无法识别的时间范围描述，按最接近的档位处理；实在无法判断就按 `一天` 处理。

## 执行前必须先做的事

1. 只读写 `project/aiNews/` 目录内的文件，不要碰仓库根的 `GLOBAL_CONTEXT.md`、`PROJECT_CONFIG.md`、`plan/`，也不要碰 `project/` 下其他同级项目。
2. 读取 `project/aiNews/sources.md`，拿到当前「可用」状态的信息源清单。
3. 确认今天的日期，计算出当日产出目录路径：`project/aiNews/{YYYY}年/{MM}月/{DD}日/`（月、日两位数补零，例如 `project/aiNews/2026年/11月/07日/`）。若目录已存在（今天已经跑过一次），直接覆盖/更新里面的文件，不要重复建目录。

## 步骤一：收集

- 依次访问 `sources.md` 中状态为「可用」的信息源，收集**指定时间范围内**发布的 AI 相关内容（新模型/新论文/新工具/行业大事件/重要开源项目等）。时间范围由上方「输入参数」决定，默认最近 1-2 天。
- 每条记录至少包含：标题、来源、链接、一句话简述、发布时间（如能拿到）。
- 去重：同一事件只保留信息最全的一条。
- 把收集到的全部原始条目写入当日目录下的 `01_collected.md`（按来源分组，Markdown 列表即可）。

### 遇到 Block 问题时的处理（重要，不要卡住流程）

如果某个信息源网站打不开、或者某个工具（搜索/抓取）调不通：

1. **不要反复重试同一个源/同一种方式**，最多尝试 2 次不同方式（例如换一种搜索方式）。
2. 跳过这个源，继续收集其他源，保证本次任务不被单点问题卡死。
3. 回到 `sources.md`：
   - 把该源的「状态」列改成 `失效-YYYY-MM-DD`；
   - 如果"替补源"表里有对应替代，优先启用一个替补源去补这次的收集（把替补源状态也更新为可用，必要时挪进主清单）；
   - 在「自愈变更日志」一节追加一条记录：`- YYYY-MM-DD｜源名｜问题现象｜本次处理方式`。
4. 这就是"自动优化这个 project"——下一次执行时，`sources.md` 已经是修复后的状态，不需要人工介入。

## 步骤二：筛选 Top 3

从 `01_collected.md` 的全部条目里，按以下标准挑出最值得关注的 3 条：

- 时效性：越新越优先（时间范围内最近发布的优先）。
- 重要性/影响力：新模型发布、重大论文突破、重要工具/产品更新、行业级事件，优先于普通资讯。
- 与「AI 技术」强相关（大模型、Agent、RAG、推理/训练技术、AI 开发工具、行业动态），过滤掉纯营销/重复炒作内容。
- 尽量覆盖不同类型（不要 3 条都是同一类，比如都是模型发布），让内容有多样性。

把选出的 3 条连同"为什么选它"的一句话理由，写入当日目录下的 `02_top3.md`。

## 步骤三：生成简要概括（给没空细看的情况用）

基于 `02_top3.md`，写一份更短的概括，写入当日目录下的 `00_summary.md`，要求：

- 开头一句话总览（今天收集到几条、整体方向/风口是什么）。
- 3 条内容各压缩成 1-2 句话（只保留"是什么 + 为什么重要"，不展开背景和细节）。
- 整个文件控制在 150-250 字以内，要做到"30 秒读完就知道今天值不值得细看"。
- 不需要链接、不需要标题结构，纯口语化短文本即可。

## 步骤四：生成掘金文章草稿

基于 `02_top3.md` 的 3 条内容，生成一篇掘金风格的文章草稿，写入当日目录下的 `03_juejin_draft.md`，要求：

- **标题**：简洁有信息量，避免标题党，体现"今日 AI 要闻/资讯"性质，可包含日期。
- **标签**：给 3-5 个掘金常用标签建议（如：人工智能、大模型、AI、机器学习、程序员 等，按实际内容选）。
- **正文结构**：
  1. 开头 1-2 句话引入，说明这是当日精选的 3 条 AI 技术动态。
  2. 每条用一个 `##` 二级标题（简述事件本身），正文包含：发生了什么、为什么值得关注、可能的影响或应用场景。
  3. 结尾做一句话小结 + 一个引导读者讨论/关注的话术。
  4. 文末附"参考链接"列表，对应 3 条的原始来源链接。
- **篇幅**：中文正文 800-1500 字左右，技术向但通俗易懂，不堆砌术语。
- **语言**：中文。

## 完成标准

当日目录 `project/aiNews/{YYYY}年/{MM}月/{DD}日/` 下存在且内容完整的四个文件：`00_summary.md`、`01_collected.md`、`02_top3.md`、`03_juejin_draft.md`；如本次执行中遇到源/工具失效，`sources.md` 已同步更新（状态 + 自愈变更日志）。
