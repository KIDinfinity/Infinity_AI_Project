# Week 07 · AI 知识库与 RAG 资产沉淀

## 1. 本周核心目标

把 AI 从「会调用模型」升级为「有知识、有评估、有迭代记录」的能力，建立知识库、测试集与 Bad Case 系统。

## 2. 为什么这一周存在

若 DA-01 需要 AI，本周决定它回答质量的上限；即使暂不需要，本周沉淀的测试集与 Bad Case 方法也是可复用资产。

## 3. 本周在整个半年路线中的位置

```
第 6 周产出：README / FAQ / 使用说明 / Demo
  ↓
本周：文档清洗 → 向量化 → 检索 → 20 条测试集 → Bad Case 系统
  ↓ 新产出
知识库 + 20 条固定测试集 + Bad Case 表 + 一轮调优
  ↓ 下一周输入
第 8 周把知识库、向量数据纳入容器化与备份/恢复
```

## 4. 本周必须留下的资产

- 知识库结构（faq/docs/examples/troubleshooting）
- 文档清洗与向量化结果
- 20 条固定测试集
- Bad Case 记录表
- 至少一轮调优

## 5. 本周验收标准（PASS/FAIL）

- [ ] 知识库结构建立
- [ ] 文档完成清洗和向量化
- [ ] Qdrant 检索稳定
- [ ] 20 条固定测试集
- [ ] Bad Case 记录表
- [ ] 至少完成一轮调优
- [ ] 能解释 RAG 各环节作用

## 6. 本周禁止事项

- 不为追求漂亮准确率数字而造假
- 不因产品暂不需要 AI 就强行接入 RAG
- 重点是「知道为什么错、怎么改」，不是堆测试数量

## 7. 如果只有 7 小时

必做：知识库 + 向量化 + 20 条测试集跑通。可删：完整调优、Bad Case 细化。

## 8. 完成本周后

下一周把前 7 周产出（代码/文档/知识库/向量数据）打包成可容器化、可备份、可恢复的数字资产。
