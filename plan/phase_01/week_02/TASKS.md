# Week 02 · TASKS

## Task 0：判断问题类型

### 做什么
把第 1 周问题池收敛，给每个痛点标注问题类型：纯软件 / AI / 自动化 / 视觉 / 物理世界 / 机器人。

### 为什么做
第 3 周要明确 DA-01，必须先知道每个痛点最适合的技术组合。

### 对 DA-01 的贡献
为 DA-01 筛选「值得做且技术组合清晰」的候选。

### 前置依赖
第 1 周问题池初稿。

### 具体执行步骤
1. 补足问题池到 ≥10 个。
2. 给每个痛点标注问题类型和可能的技术组合。
3. 初步圈出最值得深挖的 3 个。

### 验收标准
问题池每个痛点都有问题类型标注。

### 完成后的产出
已分类的问题池。

### 如果没有必要
必做（为第 3 周明确 DA-01 打底）。

## Task 1：对象存储 MinIO

### 做什么
部署 MinIO，建 `assets/documents/backups` 三个 bucket，跑通上传/下载。

### 为什么做
DA-01 的文件类资产（文档、备份、Demo）需要统一、可恢复的存放位置。

### 对 DA-01 的贡献
给 DA-01 建立文件资产存储与恢复能力。

### 前置依赖
第 1 周 Docker 环境。

### 具体执行步骤
1. 部署 MinIO。
2. 创建 bucket。
3. 上传 → 删本地 → 下载 → 校验完整。

### 验收标准
删除本地文件后能从 MinIO 完整恢复并打开。

### 完成后的产出
可用对象存储 + 3 个 bucket。

### 如果没有必要
若 DA-01 最终不需要对象存储（如纯 CLI/无文件资产），降级为 Optional。

## Task 2：向量库 Qdrant

### 做什么
部署 Qdrant，建 collection，插入测试向量，执行相似度查询。

### 为什么做
若 DA-01 需要语义检索（RAG），向量库是基础；本周只做最小验证，不等产品定形。

### 对 DA-01 的贡献
为 DA-01 可能的 AI/RAG 能力预留检索底座，并验证技术可行。

### 前置依赖
第 1 周 Docker 环境。

### 具体执行步骤
1. 部署 Qdrant。
2. 建 collection，插入 ≥5 条测试文本向量。
3. 执行相似度查询，验证返回最相关内容。

### 验收标准
相似度查询返回语义相关结果，能解释 embedding/vector/collection/similarity search。

### 完成后的产出
可用向量库 + 一次检索实验记录。

### 如果没有必要
若 DA-01 明确不需要语义检索，则删除本任务，不强行保留。

## Task 4：备份与恢复

### 做什么
完成 Git 代码、对象文件、向量数据三类备份，并做一次恢复测试。

### 为什么做
数字资产的核心验收原则是「删除后还能恢复」，而不是「部署成功」。

### 对 DA-01 的贡献
让 DA-01 具备可恢复能力，是「可持续迭代」的硬前提。

### 前置依赖
Task 1 + Task 2。

### 具体执行步骤
1. 备份三类资产。
2. 故意删除测试数据。
3. 用备份恢复并验证。

### 验收标准
删除后能从备份完整恢复并验证成功。

### 完成后的产出
备份脚本/记录 + 恢复验证记录。

### 如果没有必要
必做，不可删除（这是本周核心验收）。
