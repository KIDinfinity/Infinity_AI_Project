# Week 02 · 存储、向量库与备份体系 + 判断问题类型

## 1. 本周核心目标

建立「代码 + 文件 + 向量数据」三类资产存储底座，跑通一次备份与恢复；同时把问题池收敛并初步判断每个痛点的问题类型。

## 2. 为什么这一周存在

智能解决方案资产不能只存在本机。本周让 DA-01 的数据有了统一存放位置和恢复能力；同时判断痛点属于纯软件 / AI / 自动化 / 视觉 / 物理世界 / 机器人哪一类，为第 3 周明确 DA-01 打底。

## 3. 本周在整个半年路线中的位置

```
第 1 周产出：Git 服务 + 项目模板 + 问题池初稿
  ↓
本周：部署对象存储 + 向量库 + 备份/恢复 + 判断问题类型
  ↓ 新产出
对象存储/向量检索可用、备份恢复验证、问题池分类
  ↓ 下一周输入
第 3 周用稳定环境 + 已分类问题池确定 DA-01
```

## 4. 本周必须留下的资产

- MinIO 或等价对象存储 + bucket（assets / documents / backups）
- Qdrant 或等价向量库 + 一次相似度检索
- 三类资产的备份与恢复记录
- 问题池分类（每个痛点标注问题类型）

## 5. 本周验收标准（PASS/FAIL）

- [ ] 对象存储：上传文件 → 删本地 → 重新下载 → 文件完整
- [ ] 向量检索：≥5 条文本 → embedding → 检索返回相关内容
- [ ] 恢复：删除测试数据 → 用备份恢复 → 验证成功
- [ ] 能解释代码、对象、向量三类资产分别存在哪里
- [ ] 问题池每个痛点已标注问题类型

## 6. 本周禁止事项

- 不追求「部署成功」，只认「删除后还能恢复」
- 不因没有云服务器而阻塞（本地模拟即可）
- 不扩展到 MinIO/Qdrant 之外的更多服务
- 不因为某个痛点「看起来要硬件」就提前买设备

## 7. 如果只有 7 小时

必做：对象存储上传/下载 + 一次向量检索 + 一次备份/恢复 + 问题池分类。可删：云服务器基础环境。

## 8. 完成本周后

下一周使用稳定环境 + 已分类问题池，确定 DA-01 的问题与技术组合。
