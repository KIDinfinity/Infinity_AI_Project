# Week 04 · 解决方案冻结 + 最小感知-决策架构

## 1. 本周核心目标

把「值得做的问题」转换成足够小、能真正开发的解决方案，并跑通最小「感知 → AI → 决策」链路（能纯软件就纯软件）。

## 2. 为什么这一周存在

本周把 DA-01 从「一个方向」变成「可开发的最小规格」，同时验证 AI / 感知能力是否真的需要、怎么接。

## 3. 本周在整个半年路线中的位置

```
第 3 周产出：DA-01 主候选（问题/用户/价值/技术组合）
  ↓
本周：冻结 MVP 需求 → 定解决方案形态 → 定技术组合 → 最小感知-决策实验
  ↓ 新产出
MVP 需求冻结、解决方案形态与理由、技术方案、10 条 AI 测试集
  ↓ 下一周输入
第 5 周直接开发 MVP 核心价值链，不再改需求
```

## 4. 本周必须留下的资产

- MVP 需求冻结（用户/问题/价值/最小流程）
- 解决方案形态 + 选择理由（为什么这是最小方案）
- 技术方案（软件/AI/感知/执行按需组合）
- 最小 LLM 调用链 + 最小 RAG 链路实验（如需要）
- 10 条 AI 测试集 + 第一份 Bad Case 记录

## 5. 本周验收标准（PASS/FAIL）

- [ ] MVP 需求冻结
- [ ] 解决方案形态确定且有理由（为什么是最小方案）
- [ ] 技术组合确定（不为「具身」加不需要的硬件）
- [ ] 最小 AI 调用链跑通
- [ ] 最小 RAG 链路跑通或完成技术验证
- [ ] 建立 10 条 AI 测试集 + Bad Case 记录

## 6. 本周禁止事项

- 不为「全栈完整」加不必要的组件（能不用就不用）
- 不强行加入 AI/RAG，若产品不需要则明确记录「不需要」
- 技术栈最后才定，不被已有技能绑架

## 7. 如果只有 7 小时

必做：需求冻结 + 产品形态 + 技术方案。可删：最小 RAG 链路（若产品暂不需要 AI）。

## 8. 完成本周后

下一周根据冻结的需求与形态，开发 MVP 核心价值链。
