# Week 05 · MVP 核心价值链开发

## 1. 本周核心目标

从「方案」进入「能运行的东西」，只做核心价值链（输入→处理→结果），不追求完整。

## 2. 为什么这一周存在

第 4 周冻结了需求与方案，本周必须产生第一个能运行的核心流程，否则计划停留在纸面。

## 3. 本周在整个半年路线中的位置

```
第 4 周产出：冻结的 MVP 需求 + 产品形态 + 技术方案
  ↓
本周：实现最重要的一条用户路径，AI 协作开发
  ↓ 新产出
可运行的核心流程 + 开发资产记录
  ↓ 下一周输入
第 6 周补齐闭环、错误处理、文档与 Demo
```

## 4. 本周必须留下的资产

- 核心流程可运行（连续成功 3 次）
- README 能指导启动
- 开发资产记录（每天解决了什么、坑、如何复用）

## 5. 本周验收标准（PASS/FAIL）

- [ ] 核心流程从干净环境按 README 启动并得到预期结果
- [ ] 核心流程连续跑通 3 次
- [ ] 至少 5 个异常场景有处理
- [ ] AI 生成代码经过人工检查
- [ ] 没有「为了完整」加入非核心功能

## 6. 本周禁止事项

- 不追求完整功能，只做 A→B→C 核心链
- 不把 AI 生成代码直接当成品，必须人工验收
- 不扩大到核心价值以外的功能

## 7. 如果只有 7 小时

必做：核心流程可运行 + 连续跑通。可删：异常场景处理、开发资产记录。

## 8. 完成本周后

下一周基于核心流程补齐闭环、错误处理、文档与 3–5 分钟 Demo，让它从「开发者能跑」变成「别人能用」。
