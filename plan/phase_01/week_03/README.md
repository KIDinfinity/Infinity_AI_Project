# Week 03 · 明确 DA-01（问题 + 技术组合）

## 1. 本周核心目标

停止「我要做什么技术」，开始回答「我要解决什么真实问题、需要哪些技术组合」；从问题池收敛出 1 个主候选，明确 DA-01。

## 2. 为什么这一周存在

这是整个半年最重要的转折：DA-01 最晚本周明确。没有真实问题，后面 23 周都会变成「为了技术而技术」。

## 3. 本周在整个半年路线中的位置

```
第 1–2 周产出：稳定环境 + 已分类问题池
  ↓
本周：问题池 → 3 候选 → 1 主候选 → 验证方案
  ↓ 新产出
DA-01 候选定义（问题/用户/场景/价值/技术组合/最小方案）
  ↓ 下一周输入
第 4 周基于主候选冻结需求、定解决方案形态与技术组合
```

## 4. 本周必须留下的资产

- 问题池 ≥ 10 个（含问题类型）
- 3 个候选的结构化分析
- 1 个主候选（或明确「继续寻找」）
- 每个候选的最小验证方案 + 技术组合判断

## 5. 本周验收标准（PASS/FAIL）

- [ ] 10 个问题进入问题池
- [ ] 3 个候选完成「问题/谁有/何时/现状/改进/付费意愿/最小方案/技术组合」分析
- [ ] 选出 1 个主候选或明确继续寻找
- [ ] 能 3 分钟讲清主候选解决什么问题、用什么技术组合
- [ ] 没有因技术栈方便而强行选择方案，没有为「具身」强加硬件

## 6. 本周禁止事项

- 禁止直接进入开发
- 禁止默认解决方案形态（Web/App/小程序/全栈），也禁止默认「必须机器人/视觉」
- 禁止因为「会某个技术」而倒推选方案

## 7. 如果只有 7 小时

必做：10 个问题 + 3 个候选 + 1 个主候选。可删：为每个候选设计详细验证方案。

## 8. 完成本周后

下一周读取主候选的问题/用户/价值/技术组合，冻结 MVP 需求并确定解决方案形态与技术栈。
