# Week 01 · 研发底座初始化 + 痛点探索启动

## 1. 本周核心目标

建立统一、可复用的个人研发环境（代码托管、项目目录、环境变量、文档规范），同时启动真实痛点探索。

## 2. 为什么这一周存在

半年要持续生产智能解决方案资产，必须有一个「新项目能快速创建、代码统一托管、环境可迁移」的底座；同时从第 1 周就开始收集真实痛点，避免第 3 周临时找方向。

## 3. 本周在整个半年路线中的位置

```
（从零开始）
  ↓
本周：建立 Git 服务 + 项目模板 + 目录/环境/README 规范 + 痛点探索启动
  ↓ 新产出
Git 仓库、项目模板、.env.example、Docker 最小示例、目录规范、问题池初稿
  ↓ 下一周输入
第 2 周用统一托管方式承载存储/向量库/备份，并继续判断问题类型
```

## 4. 本周必须留下的资产

- 可用的 Git 服务（Gitea 或等价）
- 至少一个测试仓库 + 三目录结构（product-lab / ai-lab / infra）
- 一个 `digital-product-template` 项目模板
- README 模板、`.env.example`、`.gitignore`、Docker 最小示例
- 问题池初稿（≥5 个真实痛点）

## 5. 本周验收标准（PASS/FAIL）

- [ ] Docker 可用，能启动最小容器并查看/停止/删除日志
- [ ] Git 服务可用，能独立创建/提交/推送项目
- [ ] 从零创建新项目并推送，一次完成、不看教程
- [ ] 能独立解释 image / container / volume / `.env` 为什么不能提交
- [ ] 问题池初稿 ≥5 个真实痛点

## 6. 本周禁止事项

- 不部署 MinIO / Qdrant 等后续服务（那是第 2 周）
- 不搭建 CI/CD、不引入复杂工程规范
- 不因为「顺便学一下」扩大范围
- 不在痛点探索阶段预设「必须用机器人/视觉」

## 7. 如果只有 7 小时

必做：Docker 可用 + Git 服务可用 + 一个项目模板 + 问题池初稿。可删：Docker 最小示例、三目录细化。

## 8. 完成本周后

下一周读取：项目模板、目录规范、Git 服务、问题池。使用它们承载存储/向量库/备份，并继续判断问题类型。
