# Week 01 · TASKS

## Task 0：痛点探索启动

开始收集真实痛点，形成问题池初稿（≥5 个），每个一句话描述。

### 为什么做
DA-01 必须从真实问题出发，第 3 周要明确方向，不能临时找。

### 对 DA-01 的贡献
给 DA-01 提供「值得解决的问题」来源，是探索阶段的起点。

### 前置依赖
无。

### 具体执行步骤
1. 列出工作中反复遇到的问题、AI 使用痛点、自动化需求、信息整理痛点等。
2. 攒够 ≥5 个，记录来源。

### 验收标准
问题池初稿 ≥5 个，来源真实、非臆造。

### 完成后的产出
问题池初稿。

### 如果没有必要
必做（阶段一探索起点）。

## Task 1：Docker 环境

### 做什么
在 Mac 上装好 Docker，跑通最小容器，理解 image / container / volume / network 基本关系。

### 为什么做
后续 DA-01 需要可重复运行、可迁移的环境，Docker 是最小可行方案。

### 对 DA-01 的贡献
为 DA-01 建立可重复运行环境，未来可迁移到其他机器；若 DA-01 最终不需要容器化则降级。

### 前置依赖
无。

### 具体执行步骤
1. 安装并启动 Docker。
2. 跑一个最小容器（如 hello-world / nginx）。
3. 依次练习 `docker run / ps / logs / stop / rm`。

### 验收标准
能独立完成上述 5 条命令，并能口头解释 image 与 container 区别、volume 的作用。

### 完成后的产出
可用的 Docker 环境 + 最小运行示例。

### 如果没有必要
若当前机器已有稳定 Docker 且熟练，跳过；若 DA-01 形态最终不需要容器化，保留为 Optional。

## Task 2：Git 代码仓库

### 做什么
部署 Gitea 或等价 Git 服务，建立 `projects/{product-lab, ai-lab, infra}` 目录。

### 为什么做
所有数字资产必须统一托管、可追溯、可备份，避免散落本机。

### 对 DA-01 的贡献
给 DA-01 提供统一代码托管与版本历史，是「可交付、可迭代」的前提。

### 前置依赖
Task 1（Docker 可作为部署 Gitea 的载体）。

### 具体执行步骤
1. 部署 Git 服务。
2. 建测试仓库，跑通 clone / commit / push。
3. 建立三目录结构与 `projects/` 根。

### 验收标准
能独立创建新仓库、提交、推送，不看教程。

### 完成后的产出
可用的 Git 服务 + 测试仓库 + 目录结构。

### 如果没有必要
若已有可用的 GitHub/Gitea 托管，可不自建服务，直接用现有托管。

## Task 3：项目规范

### 做什么
统一 `README.md / .env.example / .gitignore / docs/ / src/ / scripts/` 结构。

### 为什么做
让每个新项目打开就有统一入口，减少每次重新决定「文件怎么放」。

### 对 DA-01 的贡献
DA-01 交付时 README 与配置可直接复用，降低交付与恢复成本。

### 前置依赖
Task 2（规范需要落到真实仓库里验证）。

### 具体执行步骤
1. 定义最小目录规范。
2. 写 README 模板与 `.env.example` 模板。
3. 在一个测试仓库中落地验证。

### 验收标准
从零用规范创建项目一次完成，README 能指导启动。

### 完成后的产出
目录规范 + README 模板 + `.env.example` 模板。

### 如果没有必要
若 DA-01 尚未明确，只保留最小结构，不建与真实产品无关的复杂模板。

---

## Task 4：工程模板

### 做什么
建立 `digital-product-template`，以后新项目直接复制。

### 为什么做
沉淀可复用模板，是「可复制生产能力」的第一块砖。

### 对 DA-01 的贡献
DA-01 及后续 DA-02/03 可快速起步，不重复搭脚手架。

### 前置依赖
Task 3（模板 = 规范 + README + .env + Docker 示例）。

### 具体执行步骤
1. 把规范、README、`.env.example`、`.gitignore`、Docker 最小示例合并成模板。
2. 提交到 Git 服务。

### 验收标准
复制模板 → 初始化 Git → 推送，一次完成。

### 完成后的产出
`digital-product-template` 模板仓库。

### 如果没有必要
只保留最小可复制结构，不加入任何 DA-01 尚未确认的组件。
