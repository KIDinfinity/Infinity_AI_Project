# Week 08 · 容器化、备份、迁移与 8 周总验收

## 1. 本周核心目标

把前 7 周产出从「本机项目」升级为「可迁移、可恢复、可继续积累的数字资产」，并完成阶段一终极验收。

## 2. 为什么这一周存在

这是阶段一的毕业考试：证明 DA-01 不是只存在于本机的 Demo，而是能迁移、能恢复、能讲清、能解释的资产。

## 3. 本周在整个半年路线中的位置

```
第 1–7 周产出：底座 + MVP + 文档 + 知识库 + 测试集
  ↓
本周：容器化 + 一键启动 + 备份 + 恢复 + 8 周终极验收
  ↓ 新产出
可迁移可恢复的 DA-01 + 8 周验收结论
  ↓ 下一周输入
第 9 周基于可运行、可恢复的 DA-01 做产品打磨测试
```

## 4. 本周必须留下的资产

- 容器化配置（按实际需要，不全量容器化）
- 一键启动方案（docker-compose 或等价）
- Git/配置/文档/知识库/向量数据/对象文件的备份
- 一次「电脑坏了」恢复验证

## 5. 本周验收标准（PASS/FAIL）

- [ ] 干净环境：代码/配置/数据恢复 → 服务启动 → 核心功能运行
- [ ] 3 分钟讲清产品（谁用/为什么用/怎么用/得到什么/为何可能付费）
- [ ] 能解释 Embedding/Vector DB/RAG/Chunk/Bad Case/幻觉
- [ ] 能说明为什么选当前产品形态、为什么没选更复杂方案

## 6. 本周禁止事项

- 不要求全部服务容器化，只容器化真正需要的部分
- 不因为「电脑没坏」就跳过恢复演练
- 不把「部署成功」当验收，只认「删除后能恢复」

## 7. 如果只有 7 小时

必做：备份 + 恢复验证 + 核心功能运行。可删：全量容器化、一键启动脚本。

## 8. 完成本周后

若 8 周总验收 PASS，进入第 9 周产品打磨测试；CONDITIONAL 则第 9 周每天抽 20 分钟补齐；FAIL 则找到最小失败点优先修复，不增加新复杂度。
