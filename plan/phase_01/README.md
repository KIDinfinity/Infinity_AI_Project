# Phase 01 · 探索与沉淀期（第 1–8 周）

## 1. 阶段目标

前 2 周探索真实痛点并判断问题类型，第 3 周明确 DA-01，第 4–8 周做出最小可运行智能解决方案并沉淀基础能力。

## 2. 为什么这个阶段存在

半年最终目标是「一个真实智能解决方案资产 + 一套可复制的生产能力」。第 1–8 周不追求赚钱，而是先找到真正值得解决的痛点、判断问题类型、做出第一个能运行的最小方案。没有这个底座，后面 18 周无法稳定放大。

## 3. 本阶段必须产生什么

- 研发底座：Docker、Git 仓库、对象存储、向量库、项目模板、备份/恢复机制。
- 真实痛点池（≥10 个）+ 问题类型判断（纯软件 / AI / 自动化 / 视觉 / 物理世界 / 机器人）。
- 一个经过验证的 DA-01 候选（问题 → 用户 → 场景 → 价值 → 技术组合 → 主候选）。
- 一个可运行的 DA-01 MVP + README + Demo。
- AI/感知-决策最小能力：LLM 调用链、Embedding、向量检索、RAG、20 条测试集、Bad Case 记录（如 DA-01 需要，加视觉/感知最小实验）。
- 可复用模板：项目 / Docker / README / 部署 / 备份 / RAG 测试 / 解决方案验证 / 周复盘。

## 4. 本阶段不应该做什么

- 不预设 DA-01 为 Web / App / 小程序 / 全栈，也不预设为「必须具身 / 必须机器人」。
- 不为学习技术而学习技术，尤其不因「具身智能很火」跳进 ROS / SLAM / 运动规划的学习坑。
- 不无限扩张基础设施，不部署当前用不到的服务，不为「具身」买用不到的硬件。
- 不因为一个候选方向失败就认为整个计划失败。

## 5. 本阶段核心能力

容器化部署、Git 规范、对象存储与向量检索基础、真实问题验证方法、问题类型判断、最小 AI/RAG 链路、备份恢复。

## 6. 本阶段与 DA-01 的关系

这是 DA-01 的「出生期」：第 1–2 周探索痛点并判断问题类型，第 3 周明确 DA-01，第 4–7 周做出 MVP 并接入 AI，第 8 周让它可迁移、可恢复、可验收。

## 7. 进入条件

阶段一 · 第 1 周开始，无前置产出（从零建立）。

## 8. 完成条件

第 8 周终极验收通过：干净环境恢复并运行核心功能；3 分钟讲清产品；能解释 AI 技术原理；能说明为什么选当前产品形态。

## 9. 阶段验收标准

第 8 周「8 周最终验收清单」A/B/C/D 四类全部 PASS，或核心项 PASS + 非核心项 CONDITIONAL。

## 10. 下一阶段依赖什么

阶段二依赖：已验证的 DA-01 主候选、可运行 MVP、完整 README、可恢复的环境——这些是第 9 周「产品打磨测试」的输入。

## 完成本阶段后，DA-01 比阶段开始前多了什么？

从「什么都没有」变成：一个固定的研发底座 + 一个已经验证方向、可运行、可恢复、有 AI 能力的第一版数字资产 + 一套可复用模板。
