# Week 06 · TASKS

## Task 1：补齐核心闭环

### 做什么
完成「进入→使用→核心功能→得到结果→退出/保存/导出」完整链。

### 为什么做
只有核心流程不算闭环，用户需要完整的进出与结果保存。

### 对 DA-01 的贡献
让 DA-01 形成可独立使用的完整最小闭环。

### 前置依赖
第 5 周核心流程。

### 具体执行步骤
补齐进入、结果保存/导出、退出环节。

### 验收标准
完整闭环可独立走通。

### 完成后的产出
完整 MVP 闭环。

### 如果没有必要
必做。

---

## Task 2：错误处理

### 做什么
处理空输入、错误输入、API 错误、超时、空数据、服务不可用。

### 为什么做
可交付产品必须能优雅处理异常，否则陌生用户一用就崩。

### 对 DA-01 的贡献
提升 DA-01 的可用性与可信度。

### 前置依赖
Task 1。

### 具体执行步骤
逐类场景测试并加处理。

### 验收标准
至少 5 个异常场景有明确处理。

### 完成后的产出
错误处理清单与测试记录。

### 如果没有必要
必做。

---

## Task 3：文档

### 做什么
写 README / 安装 / 启动 / 配置 / 使用 / FAQ / 已知问题。

### 为什么做
文档是「别人能用」的入口，也是第 7 周知识库的原料。

### 对 DA-01 的贡献
让 DA-01 可交付、可独立使用，并沉淀为知识资产。

### 前置依赖
Task 1。

### 具体执行步骤
按模板补齐 README 各节。

### 验收标准
陌生用户只看文档能独立完成核心任务。

### 完成后的产出
完整 README 与文档。

### 如果没有必要
必做。

## Task 4：最小演示

### 做什么
录制/保存 3–5 分钟完整演示，证明「真的能用」。

### 为什么做
用最小成本记录产品可用性，为后续售卖物料打底。

### 对 DA-01 的贡献
给 DA-01 提供第一份可对外展示的证据。

### 前置依赖
Task 1–3。

### 具体执行步骤
录制核心流程演示，不追求营销效果。

### 验收标准
3–5 分钟演示完成，覆盖核心流程。

### 完成后的产出
Demo 文件。

### 如果没有必要
若时间不足可降级为文字版截图说明。
