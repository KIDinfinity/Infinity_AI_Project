# Week 06 · MVP 闭环与可交付性

## 1. 本周核心目标

让产品从「开发者能运行」变成「别人也能使用」，补齐闭环、错误处理、文档与 Demo。

## 2. 为什么这一周存在

「能跑」不等于「能交付」。本周把 MVP 补成陌生用户也能按文档独立使用的最小可交付版本。

## 3. 本周在整个半年路线中的位置

```
第 5 周产出：可运行核心流程
  ↓
本周：补齐闭环 + 错误处理 + 文档 + 3–5 分钟 Demo
  ↓ 新产出
Clean Install 通过、陌生用户模拟通过、README 完整、Demo
  ↓ 下一周输入
第 7 周基于产品文档与 FAQ 搭建知识库与 RAG 资产
```

## 4. 本周必须留下的资产

- 完整核心闭环（进入→使用→结果→退出/保存/导出）
- README + 安装/配置/FAQ/已知问题
- 3–5 分钟 Demo
- 核心 Bug 列表 + 已知限制

## 5. 本周验收标准（PASS/FAIL）

- [ ] 核心流程完整
- [ ] Clean Install 成功（干净环境按 README 独立完成）
- [ ] 陌生用户模拟成功（不看源码、只看 README 完成核心任务）
- [ ] README 完整
- [ ] 3–5 分钟 Demo 完成
- [ ] 核心 Bug 列表 + 已知限制记录

## 6. 本周禁止事项

- 不追求营销级 Demo，只证明「真的能用」
- 不临时手把手帮用户操作才算通过
- 不为「完整」加入非核心功能

## 7. 如果只有 7 小时

必做：Clean Install + 陌生用户模拟 + README。可删：Demo 录制、Bug 列表细化。

## 8. 完成本周后

下一周用 README/FAQ/使用说明作为知识库原料，搭建 RAG 与 AI 评估体系。
