## 7. 本周验收标准

- [ ] PASS / FAIL：facts.md 每条事实有「数字 + 来源文件路径 / 链接 + 日期」
- [ ] PASS / FAIL：三版简历各 1 页，每版 bullet 都能在 facts.md 中找到对应条目
- [ ] PASS / FAIL：每版至少 3 个量化 bullet（来自 Eval v2 / p3-notes / 安全报告 / 使用统计）
- [ ] PASS / FAIL：无公司机密（不写公司内部系统名、业务数据），无夸大（「参与」与「主导」区分清楚）
- [ ] PASS / FAIL：LLM 招聘方挑刺至少 1 轮，修订记录可见
- [ ] PASS / FAIL：applications.md 已建，3–5 个岗位已投递，每个有 JD 匹配度与定制点

## 8. 求职映射

- 本周能力：简历写作（STAR / XYZ 公式）、JD 分析、岗位定位、求职漏斗管理。
- 简历 bullet 草稿：本周即产出简历本身。
- 面试题：
  1. 为什么从前端转 AI 工程？（答要点：前端/全栈背景 → 看到 AI 应用的工程短板（评测/安全/交付）→ 半年用一个真实系统验证 → 数字证据）
  2. 你简历上的「rubric 通过率 0.**」是怎么算的？（答要点：20 条场景集、5 维 rubric、≥ 7/10 通过、judge 经 10 条人审校准一致率 **）
  3. 这个项目是工作项目还是个人项目？（答要点：个人项目，解决自己工作中的真实痛点，使用脱敏/公开数据，遵守公司合规）

## 9. 本周禁止事项

- 不编造经历、不夸大数字、不把个人项目包装成公司项目。
- 不在简历或投递中出现公司机密。
- 不主动私信 / 社群营销 / 群发（总约束：仅被动沟通）；只用招聘网站与官网正常投递。
- 不海投（> 5 个）；本周目标是质量与反馈，不是数量。
- 不裸辞。
