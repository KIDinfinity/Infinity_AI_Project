# Week 14 · TASKS

## Task 1：监控访客咨询

### 做什么
监控官网访客与 Agent 咨询，记录真实问题。

### 为什么做
真实咨询是理解用户、验证产品的第一手数据。

### 对 DA-01 的贡献
给 DA-01 提供真实需求信号。

### 前置依赖
第 12–13 周 Agent + 流量。

### 具体执行步骤
每天查看咨询记录并归类。

### 验收标准
有真实访客咨询被记录。

### 完成后的产出
访客咨询记录。

### 如果没有必要
必做。

## Task 2：迭代知识库

### 做什么
根据真实问题更新 FAQ 与知识库，优化 Agent 回答。

### 为什么做
真实问题暴露知识库盲区，迭代才能提高转化。

### 对 DA-01 的贡献
让 Agent 更准，降低人工沟通成本。

### 前置依赖
Task 1。

### 具体执行步骤
把高频新问题补入知识库并重新向量化。

### 验收标准
知识库按真实问题完成一轮迭代。

### 完成后的产出
知识库迭代记录。

### 如果没有必要
若无需 AI 则跳过。

## Task 3：跑首单

### 做什么
推动第一笔付费订单，坚持不接定制外包。

### 为什么做
首单是「睡后收入」能否成立的关键证据。

### 对 DA-01 的贡献
验证 DA-01 的商业价值。

### 前置依赖
第 11 周支付链路 + Task 1–2。

### 具体执行步骤
1. 跟进真实咨询。
2. 完成标准产品售卖，拒绝定制外包。
3. 记录成交或未成交原因。

### 验收标准
第一笔订单成交，或记录明确未成交原因。

### 完成后的产出
首单记录。

### 如果没有必要
必做（阶段二核心目标）。
