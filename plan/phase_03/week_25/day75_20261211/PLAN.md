## 5. 执行步骤

### 5.1 写 STAR 故事（0–30 min）

每个 STAR 格式：

```markdown
### STAR-{序号}：{一句话标题}（对应 P{1/2/3}）

**情境（Situation）**：

- {1–2 句，设定背景}

**任务（Task）**：

- {1 句，你要解决什么问题}

**行动（Action）**：

- {3–5 bullet，你做了什么，用行动动词：设计/实现/评测/优化/重构}
- 体现技术决策：「选了 X 而不是 Y，因为 Z」

**结果（Result + 数字）**：

- {2–3 bullet，每个含数字}
- 如：检索 MRR@5 从 0.62 提升到 0.81
- 如：20 条攻击用例拦截率 100%
```

三个 STAR 分配：

| STAR | 对应 | 主题建议                                   |
| ---- | ---- | ------------------------------------------ |
| 1    | P1   | 从零搭建 RAG 知识库并建立评测体系          |
| 2    | P2   | 实现可审批的 Agent 工作流（HITL + MCP）    |
| 3    | P3   | 生产化：多租户安全 + 场景评测 + 自动化部署 |

### 5.2 STAR 自检（30–35 min）

每个 STAR 检查：

- [ ] 有数字（至少 2 个量化结果）
- [ ] 行动用动词开头（设计/实现/评测/优化/重构，不是「参与」「负责」）
- [ ] 体现了技术决策（为什么选 A 不选 B）
- [ ] 能在 2 分钟内讲完

### 5.3 LLM 模拟面试（35–105 min）

**技术面 Prompt**（35–70 min）：

```
你是 AI Full-Stack 岗位的技术面试官。候选人简历见附件。
请进行 30 分钟技术面试：
1. 从 AI 基础 / RAG / Agent / Engineering 各问 1–2 题
2. 给 1 道系统设计口头讨论（候选人画架构图，你追问）
3. 对每个回答给出：✅ 好的 / ⚠️ 可改进 / ❌ 需要重学
4. 面试结束后给出总体评价 + Top 3 改进建议
```

**项目面 Prompt**（75–100 min）：

```
你是 AI Full-Stack 岗位的面试官，正在深挖候选人的项目经历。
候选人做了 WorkPilot（AI 研发助手平台，三个里程碑 P1/P2/P3）。
请进行 25 分钟项目深挖：
1. 从 P1/P2/P3 各问 1–2 个深挖问题（为什么这样设计？遇到什么困难？怎么解决的？）
2. 追问数字来源（"你说的 0.81 是怎么算出来的？"）
3. 对每个回答给出反馈
4. 面试结束后给出总体评价 + Top 3 改进建议
```

## 6. 概念自查（做完后口头回答）

- [ ] STAR 和 CAR（Challenge-Action-Result）有什么区别？（答：本质相同，STAR 多了 Situation 设定背景；面试中用 STAR 更完整）
- [ ] 如果面试官追问「这个数字怎么算的」答不上来怎么办？（答：诚实说「我需要查一下报告」，然后事后补充；不编造——这就是为什么 facts.md 每个数字都有来源）
- [ ] 模拟面试和真实面试最大的差距是什么？（答：压力不同；模拟面试的价值在于暴露「以为自己懂了但讲不清楚」的盲区）
