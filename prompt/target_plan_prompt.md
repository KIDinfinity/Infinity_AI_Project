# target_plan_prompt — 给任意 target 生成 plan_ai 风格的完整计划

> 用途：你只需要描述一个「目标（target）」，这个 prompt 就指导产出与 `plan/plan_ai/` 同构的一套完整计划（目标蓝图 + 阶段 + 周 + 天），每个 day 都要有「当天做什么 + 当天做的事和最终 target 的关系 + 具体执行步骤 + 可验收标准」。

---

## 一、输入（用户只给这些）

```text
target = 一句话描述要达成的目标（例如：三个月学会用钢琴演奏「诀别书」全曲）
约束 = {
  每日投入时长,      // 例如 60 分钟
  总周期,            // 例如 12 周
  每周固定练习天数,  // 例如 4 天（也可以是 7 天，按用户要求）
  起点水平,          // 例如 零基础 / 入门 / 有基础
  可选：参考谱子/资料路径
}
输出目录 = /Users/infinity/Documents/a_future/plan/plan_<name>
```

## 二、输出目录结构（必须与 plan_ai 一致）

```text
plan/plan_<name>/
├── README.md                       # 计划总览：目标、阶段、周、目录结构
├── TARGET.md                       # 目标蓝图：最终目标、里程碑、每日结构、核心原则
├── GENERATED_WITH.md               # 生成记录：本 plan 用了哪些 tool/agent/skill/脚本/依赖（见第七节）
├── phase_01/ … phase_03/           # 阶段（3 个左右，按 target 拆分）
│   ├── README.md                   # 阶段目标、策略、周次概览、里程碑
│   └── week_NN/
│       ├── README.md               # 本周标题 + 周期 + 主题
│       ├── TASKS.md                # 本周目标、Day 概览表
│       └── dayNN_YYYYMMDD/
│           └── PLAN.md             # 当天详细计划（见第五节模板）
```

## 三、拆解原则

1. **目标分细化**：把大目标拆成 3 个阶段、每阶段 3–4 周、每周 4–7 天；每个阶段末尾设一个可验收里程碑（M1/M2/M3…）。
2. **循序渐进**：前段打基础（不急于上主目标），中段推进核心，后段打磨成型。参考相关领域基础书籍/教程的方法（如练琴：先右手→再左手→再双手，慢速→原速→表现力）。
3. **每天只做一件事**：每天聚焦一个最小可验收单元（如 2–4 小节 / 一个模块），不贪多。
4. **锚点一致性**：每个 day 都必须能回答「今天练的，和最终 target 有什么关系」——找不到关系的任务要降级或删除。

## 四、里程碑（写进 TARGET.md）

每个里程碑 = `时间 + 可验收标准`，例如：

| 里程碑 | 时间 | 验收标准 |
|--------|------|----------|
| M1 | 第 4 周末 | 右手能完整、不断、不错地弹全曲旋律 |
| M2 | 第 8 周末 | 双手能慢速合奏全曲，节奏基本正确 |
| M3 | 第 10 周末 | 原速完整演奏，无明显错误 |
| M4 | 第 12 周末 | 有表现力地完整演奏 + 录制成品 |

## 五、day 的 PLAN.md 模板（必须逐项写满，禁止空模板）

```markdown
# Day NN · YYYY-MM-DD · Week NN · 标题

## 0. 今天只做一件事

一句话：今天聚焦「XX」（具体到小节/行/模块），达成「YY」。

不碰：ZZ（明天/下周才碰的内容，明确划清边界）。

## 1. 资产锚点（今天和最终目标的关系）

- 里程碑：M? — 说明（对应 TARGET.md 的哪个里程碑）
- 今天练完，「最终 target」多了什么（可验收/可测量）：……
- 练的东西 → 最终目标的关系：今天的 XX 是全曲/全目标的哪一块，为什么必须现在练

## 2. 起点（前置确认）

- 已有：前一天的完成项 / 已掌握的能力
- 需确认：……（如节拍器速度、昨天的难点是否解决）

## 3. 验收对齐（今天做完要能勾掉）

- [ ] 具体、可测量的验收 1
- [ ] 具体、可测量的验收 2
- [ ] ……

## 4. 时间块（≤ 每日投入时长）

| 时间 | 优先级 | 内容 |
| --- | --- | --- |
| 0–5 min | P0 | 热身：…… |
| 5–40 min | P0 | 主练：…… |
| 40–50 min | P0 | 复习：…… |
| 50–60 min | P1 | 总结：…… |

时间不足时最低保留：……

## 5. 今日练习/执行要点（只练完成今天目标必须的）

- ……
- ……

## 6. 执行步骤（具体到小节/动作/命令）

### Step 1 · ……（x min）
……（写清具体做什么、做到什么程度）

### Step 2 · ……（x min）
……

## 7. 易错点 / 常见坑

- ……
- ……

## 8. 时间不够时（最小保留）

……

## 9. 完成记录

- 实际用时：___ min
- 完成度：___%
- 难点记录：
- 明日重点：
```

## 六、必须遵守的硬规则

1. **每个 day 的 PLAN.md 都必须有「第 1 节 资产锚点」**，写清「当天内容 → 最终 target 的关系」，缺这一节 = 不合格。
2. **第 3 节验收要可测量**（能勾掉），不能是「多练习」这种空话。
3. **第 6 节步骤要具体到最小单元**（小节号 / 行 / 具体动作 / 具体命令）。
4. 参考 `plan/plan_ai/phase_02/week_09/day34_*/PLAN.md` 的密度与风格；不要生成像 `plan_piano` 旧版那样的同质空模板。
5. 每周固定练习天数 = 用户给的数值；剩余天数可作为「复习/弹性」日，不要省略日期连续性。
6. **必须在 plan 根目录生成 `GENERATED_WITH.md`**（见第七节），记录本 plan 从生成到落地的全过程用了哪些 tool、agent、skill、脚本、外部依赖，便于日后复现或迁移。

## 七、GENERATED_WITH.md 模板（放在 plan 根目录）

```markdown
# GENERATED_WITH — 本 plan 的生成与落地记录

> 记录「这个 plan 是怎么被做出来的」：用了哪些 prompt / tool / agent / skill / 脚本 / 外部依赖，方便日后复现或迁移到下一个 target。

## 1. 规划方式
- 驱动 prompt：prompt/target_plan_prompt.md（或用户临时描述）
- 拆解原则：……（目标分细化 / 循序渐进 / 每天只做一件事）

## 2. 用到的 prompt / 文档
- <文件路径> — 作用

## 3. 用到的工具 / 脚本
| 工具/脚本 | 作用 | 状态 |
|-----------|------|------|
| … | … | 已用 / 未用 |

## 4. 用到的 agent / skill
- <agent 或 skill 名> — 作用（若没用则写「无」）

## 5. 外部依赖 / 环境
- <软件/库/版本> — 作用

## 6. 关键产物
- <产物路径> — 说明
```
